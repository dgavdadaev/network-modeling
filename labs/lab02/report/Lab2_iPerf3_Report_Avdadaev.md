| Термин | Обозначение / пояснение |

| JSON | текстовый формат обмена данными, использованный для сохранения результата iPerf3 |

# Теоретические вводные данные

iPerf3 является клиент-серверным инструментом для измерения пропускной способности между двумя конечными устройствами. Сервер запускается с ключом `-s`, а клиент подключается к серверу с ключом `-c` и адресом удалённого хоста. В TCP-режиме iPerf3 показывает объём переданных данных, скорость передачи, число повторных передач и размер окна перегрузки. В UDP-режиме дополнительно отображаются jitter и потери дейтаграмм.

В Mininet сетевые узлы создаются как виртуальные хосты Linux, соединённые через виртуальные коммутаторы. В работе использовалась простая топология `h1—s1—h2`, где хост `h1` выступал клиентом, а `h2` - сервером iPerf3.

**Техническое оснащение:**

- iperf3_plotter с legacy-скриптами для построения графиков.

**Методы проведения работы:**

- интерактивное создание топологии Mininet командой `sudo mn --topo=single,2 -x`;
- запуск iPerf3-сервера на `h2` и клиента на `h1`;
- изменение параметров теста с помощью ключей `-t`, `-i`, `-n`, `-u`, `-p`, `-1`;
- экспорт результата в JSON с помощью ключа `-J`;
- визуализация результата с помощью `plot_iperf.sh`.

# Анализ результатов

В TCP-экспериментах средняя пропускная способность находилась примерно в диапазоне от 19 до 25 Gbit/s. Высокие значения объясняются тем, что трафик передавался между виртуальными хостами внутри одной виртуальной среды Mininet, а не через физическую сеть с реальными ограничениями среды передачи.

Параметр `-t 5` подтвердил возможность ограничения длительности теста: передача завершилась за 5 секунд. Параметр `-i 2` изменил частоту отчёта: вместо интервалов по 1 секунде результат выводился каждые 2 секунды. Параметр `-n 16G` завершил эксперимент после передачи указанного объёма данных.

UDP-эксперимент показал другую структуру отчёта: вместо `Retr` и `Cwnd` появились `Jitter` и `Lost/Total Datagrams`. Потери датаграмм в выполненном опыте не зафиксированы: `0/906 (0%)`. Проверка порта `3250` показала, что сервер и клиент могут работать на нестандартном порту. Параметр `-1` показал, что сервер может принять одного клиента и автоматически завершить работу.
