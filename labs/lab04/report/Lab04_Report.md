# Теоретическое введение

**Mininet** создаёт виртуальные хосты, коммутаторы и сетевые соединения на одном Linux-узле. **NETEM** — дисциплина очередей Linux, управляемая утилитой `tc`; она вносит заданные задержки и случайные вариации на выходе сетевого интерфейса.

**RTT** (Round-Trip Time) — время от отправки ICMP-запроса до получения ответа. Поскольку NETEM действует на исходящий интерфейс, задержка 100 мс на `h1-eth0` увеличивает RTT приблизительно на 100 мс; при дополнительной задержке 100 мс на `h2-eth0` ожидается приблизительно 200 мс. Реальное RTT включает накладные расходы виртуальной среды.

**Джиттер** — изменение задержки между пакетами. В записи `delay 100ms 10ms` первый параметр задаёт базовую задержку, второй — вариацию. Дополнительный `25%` задаёт корреляцию последовательных случайных значений, а `distribution normal` выбирает нормальный закон их формирования.

Для статистической оценки использованы: минимум, среднее, максимум и стандартное отклонение RTT. В интерактивной части приведено поле `mdev` непосредственно из `ping`, а в автоматической части стандартное отклонение вычислено программой Python с `statistics.pstdev` по значениям `ping.dat`.

Топология экспериментов:

```text
h1 (10.0.0.1) ---- s1 ---- h2 (10.0.0.2)
       NETEM                 NETEM (только в двусторонних опытах)
```

## 2. Интерактивные эксперименты NETEM

### 2.1. Постоянная задержка 100 мс на одном и двух хостах

На исходящем интерфейсе первого хоста введена задержка:

```bash
sudo tc qdisc add dev h1-eth0 root netem delay 100ms
ping -c 6 10.0.0.2
```

![RTT после добавления 100 мс только на h1](image/4.png){#fig-lab04-04 width=87%}

Средний RTT вырос до **102,922 мс**, что близко к заданной односторонней задержке.

Затем на `h2-eth0` также установлена задержка 100 мс:

```bash
sudo tc qdisc add dev h2-eth0 root netem delay 100ms
```

![Двусторонняя задержка: RTT в среднем 205,462 мс](image/5.png){#fig-lab04-05 width=87%}

В двустороннем опыте измерено `min=201,560`, `avg=205,462`, `max=217,713`, `mdev=5,815` мс. Таким образом, две выходные задержки по 100 мс суммируются в RTT.

### 2.2. Изменение задержки до 50 мс

Действующие правила изменены на обоих интерфейсах:

```bash
sudo tc qdisc change dev h1-eth0 root netem delay 50ms
sudo tc qdisc change dev h2-eth0 root netem delay 50ms
ping -c 6 10.0.0.2
```

![Измерение RTT при задержке 50 мс на каждом хосте](image/6.png){#fig-lab04-06 width=87%}

Средний RTT составил **114,759 мс**, а минимальный — **101,049 мс**. Значения близки к ожидаемым 100 мс с учётом накладных расходов.

### 2.3. Удаление правил

После выполнения `tc qdisc del` на обоих интерфейсах базовая задержка восстановилась:

```bash
sudo tc qdisc del dev h1-eth0 root netem
sudo tc qdisc del dev h2-eth0 root netem
ping -c 6 10.0.0.2
```

![Проверка сети после удаления правил NETEM](image/7.png){#fig-lab04-07 width=87%}

Получено `min=0,072`, `avg=0,315`, `max=0,814`, `mdev=0,313` мс, потери 0 %.

### 2.4. Джиттер, корреляция и распределение задержки

На `h1` последовательно выполнены три независимых сценария. Перед установкой нового режима предыдущая дисциплина NETEM удалялась.

```bash
# Джиттер
sudo tc qdisc add dev h1-eth0 root netem delay 100ms 10ms
ping -c 6 10.0.0.2

# После очистки: корреляция 25 %
sudo tc qdisc add dev h1-eth0 root netem delay 100ms 10ms 25%
ping -c 20 10.0.0.2

# После очистки: нормальное распределение
sudo tc qdisc add dev h1-eth0 root netem delay 100ms 20ms distribution normal
ping -c 10 10.0.0.2
```

### 3.2. Программа эксперимента

В Python API Mininet создаются `h1`, `h2`, `s1` и `c0`, затем на обоих исходящих интерфейсах устанавливается по 100 мс задержки. После 10-секундной паузы хост `h1` выполняет 100 ICMP-запросов к `h2`. Конвейер `grep` / `awk` / `sed` извлекает порядковый номер запроса и RTT, формируя двухколоночный файл `ping.dat`.

Ключевой фрагмент `lab_netem_i.py`:

```python
h1.cmdPrint('tc qdisc add dev h1-eth0 root netem delay 100ms')
h2.cmdPrint('tc qdisc add dev h2-eth0 root netem delay 100ms')
time.sleep(10)
h1.cmdPrint(
    'ping -c 100', h2.IP(),
    '| grep "time=" | awk \'{print $5, $7}\' | '
    'sed -e \'s/time=//g\' -e \'s/icmp_seq=//g\' > ping.dat'
)
```

Полная программа хранится в [`simple-delay/lab_netem_i.py`](https://github.com/dgavdadaev/network-modeling/blob/develop/labs/lab04/project/simple-delay/lab_netem_i.py).

### 3.3. Визуализация и автоматизация

Для Gnuplot создан скрипт `ping_plot`. Makefile запускает Python-программу, корректирует владельца данных, строит график, а цель `clean` удаляет полученные `.dat` и `.png`-файлы.

```makefile
all: ping.dat ping.png stats

ping.dat:
	sudo python lab_netem_i.py
	sudo chown mininet:mininet ping.dat

ping.png: ping.dat
	./ping_plot

stats: ping.dat
	python3 ping_stats.py

clean:
	-rm -f *.dat *.png
```

# Выводы

В ходе работы создана виртуальная сеть из двух хостов и одного коммутатора, выполнены интерактивные и воспроизводимые эксперименты с NETEM.
