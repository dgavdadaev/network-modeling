# Правила внесения изменений

Репозиторий содержит учебные лабораторные работы. Главные требования к изменениям — ясная история Git, воспроизводимые шаги выполнения и отсутствие случайных изменений в соседних лабораторных.

## Организация материалов

- Все материалы конкретной работы располагаются внутри `labs/labNN/`.
- Исходный код, конфигурации и результаты — в `project/`.
- Markdown, изображения, DOCX и PDF отчёта — в `report/`.
- Markdown, изображения, PowerPoint и PDF презентации — в `presentation/`.
- Ссылки на изображения в Markdown должны работать при открытии файла на GitHub.

## Работа с Git

1. Проверьте текущую ветку командой `git status -sb`. Обычно работа ведётся в `develop`.
2. Вносите изменения только в необходимые каталоги.
3. Используйте осмысленные коммиты, например `feat(lab03): ...`, `test(lab03): ...`, `docs(lab03): ...`, `fix(lab03): ...`.
4. Перед коммитом проверьте `git diff --check` и `git diff --cached --stat`.
5. Не добавляйте `node_modules/`, виртуальные машины, временные файлы и личные токены.
6. Публикуйте тег релиза лабораторной отдельно, например `lab03-v1.0.0`, не изменяя теги других работ.

## Проверка воспроизводимости

Для каждого эксперимента сохраняйте используемые параметры, команды запуска и реальные измерения. Не заменяйте результаты предполагаемыми значениями. Если два прогона дали разные результаты, указывайте оба и оговаривайте ограничения сравнения.

Если обнаружена ошибка в существующей работе, исправляйте её отдельным коммитом с пояснением причины.
