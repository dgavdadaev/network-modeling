# Git-процесс репозитория Network Modeling

В репозитории используется Git с отдельными тематическими коммитами и тегами выпусков лабораторных работ. Рабочая ветка — `develop`.

## Проверка состояния

```bash
git status -sb
git remote -v
git log -5 --oneline
```

## Коммиты

Типичные сообщения:

```text
feat(lab03): add Mininet topology configurations
test(lab03): add iPerf3 measurements and plots
docs(lab03): add report and presentation
fix(lab03): correct Markdown image paths
```

При добавлении файлов указывайте точные пути: `git add -- labs/lab03/report`, а не `git add .`, если в рабочем дереве есть временные файлы.

## Отправка изменений

```bash
git push origin develop
```

Если используется дополнительный сервер GitVerse, сначала проверьте настройку `git remote -v` и историю удалённой ветки. Не выполняйте принудительную отправку (`--force`) без отдельного анализа.

## Теги и релизы

Каждая лабораторная получает собственное пространство тегов, например:

```bash
git tag -a lab03-v1.0.0 -m "Laboratory 03: completed experiment, report and presentation"
git push origin lab03-v1.0.0
```

Создавайте тег только после окончательной проверки материалов и убедившись, что он ещё не существует. Старые общие теги (`v2.0.0`, `v3.0.0` и другие) не переиспользуются для нового релиза.

Релиз на GitHub создаётся отдельно на странице **Releases** с выбранным тегом и прикреплёнными итоговыми материалами.

## Важное правило

Не удаляйте чужие лабораторные и служебные файлы шаблона массовыми командами. Перед удалением проверяйте их назначение и `git diff --cached --name-status`.
